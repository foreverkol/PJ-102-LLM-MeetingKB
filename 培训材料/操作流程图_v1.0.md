## 2. 跑批流程（详细）

### 2.1 单文件处理流程

```
source file (.md)
    ↓
[Step 1] 读取内容
    ↓
[Step 2] 计算 content_hash
    ↓
[Step 3] 检查 WIKI 是否已存在
    ├── 存在 → 跳过
    └── 不存在 → 继续
    ↓
[Step 4] 12 步串行处理
    ├── S1: 基础信息（规则，<1s）
    ├── S2: LLM 场景识别（10s）
    ├── S3: LLM 标准摘要（13s）
    ├── S4: LLM FJV（16s）
    ├── S5: LLM 隐性知识 ×3（25s）
    ├── S6: LLM 5 类实体（17s）
    ├── S7: LLM 决策+行动（16s）
    ├── S8: LLM 风险+盲区（13s）
    ├── S9: LLM 知识归类（6s）
    ├── S10: LLM 认知提炼（13s）
    └── S11: LLM 价值评级（6s）
    ↓
[Step 5] 生成 Markdown
    ↓
[Step 6] 写入 WIKI 文件
    ↓
[Step 7] 记录日志
    ↓
下一个文件
```

### 2.2 全量跑批流程

```
[开始] python3 pipeline.py
    ↓
[Step 1] 加载 index.json
    ↓
[Step 2] 初始化 LLMClient
    ↓
[Step 3] 遍历 samples
    ├── 对每个 sample:
    │   ├── 调用 process_one()
    │   ├── 调用 s12_write_wiki()
    │   └── 打印进度
    ↓
[Step 4] 汇总统计
    ↓
[Step 5] 退出
```

## 3. 故障处理流程

```
发现问题（用户/监控）
    ↓
查看日志（tail /tmp/pj102_*.log）
    ↓
判断故障类型
    ├── LLM 调用失败
    │   ├── 401 → 检查 API key
    │   ├── 404 → 检查 base_url
    │   ├── 429 → 限流（自动重试）
    │   ├── 5xx → 服务异常（等待）
    │   └── timeout → 自动重试
    ├── JSON 解析失败
    │   └── 自动容错（safe_json_parse）
    ├── 文件不存在
    │   └── 跳过 + 警告
    └── 网络中断
        └── 等待恢复 + 重跑
    ↓
解决方案（参考故障处理手册）
    ↓
执行修复
    ↓
验证恢复
    ↓
继续跑批
```
