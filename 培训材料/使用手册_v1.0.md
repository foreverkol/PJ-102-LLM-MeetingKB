# PJ-102-LLM-MeetingKB · 使用手册 v1.0

## 1. 项目简介

PJ-102-LLM-MeetingKB 是一个**完全独立**的会议转写→知识库处理项目，使用 LLM 真实调用（默认 MiniMax M3）+ 12 步 pipeline。

**特点**：
- ✅ 不依赖其他 PJ 项目
- ✅ 旧 WIKI 不移植（重新生成）
- ✅ 12 步全流程
- ✅ LLM 真实调用

## 2. 快速开始（5 分钟上手）

### 2.1 前置条件

1. **WSL Ubuntu** 环境
2. **Python 3.11+**
3. **网络连接**（访问 api.minimaxi.com）
4. **API key**（从 `~/.hermes/.env` 读取 `MINIMAX_API_KEY`）

### 2.2 第一次使用

```bash
# 1. 验证环境
python3 --version  # 3.11+
echo $MINIMAX_API_KEY  # 应 > 100 字符

# 2. 切换到代码目录
cd /mnt/d/BaiduSyncdisk/hermes/01-项目/PJ-102-LLM-MeetingKB/03-执行/code

# 3. 测试 1 个样本
python3 pipeline.py --limit 1

# 4. 查看结果
cat /mnt/d/BaiduSyncdisk/hermes/02-知识库/PJ-102-LLM-MeetingKB/meetings/*.md
```

### 2.3 标准用法

```bash
# 跑全量
python3 pipeline.py

# 限制样本数
python3 pipeline.py --limit 10

# 清空旧 WIKI 后跑
python3 pipeline.py --clear

# 跳过 LLM（mock 测试）
python3 pipeline.py --no-llm

# 干跑（不写文件）
python3 pipeline.py --dry-run

# 指定 provider
python3 pipeline.py --provider deepseek
```

## 3. 命令详解

### 3.1 `pipeline.py` 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--limit N` | 限制样本数 | 0（全部）|
| `--no-llm` | 跳过 LLM 调用（用 mock）| False |
| `--clear` | 先清空 WIKI 目录 | False |
| `--dry-run` | 干跑，不写文件 | False |
| `--provider X` | LLM provider（minimax/deepseek/openai/anthropic）| auto |

## 4. 12 步 Pipeline 详解

每个源文件经过 12 步处理生成 WIKI：

| 步骤 | 名称 | LLM？| 说明 |
|---|---|---|---|
| S1 | 基础信息 | ❌ | 提取 title/date/时长 |
| S2 | 场景识别 | ✅ | client_visit/team_meeting 等 |
| S3 | 标准摘要 | ✅ | 6 字段（背景/问题/方法/结果/洞察）|
| S4 | FJV | ✅ | 5 facts + 5 judgments + 5 values |
| S5 | 隐性知识 | ✅×3 | 体验/判断/关系 |
| S6 | 5 类实体 | ✅ | persons/orgs/concepts/products/projects |
| S7 | 决策+行动 | ✅ | decisions + action_items |
| S8 | 风险+盲区 | ✅ | risks + blindspots |
| S9 | 知识归类 | ✅ | knowledge_type + tags |
| S10 | 认知提炼 | ✅ | 思维框架 + 数字人素材 |
| S11 | 价值评级 | ✅ | relevance/actionability/innovation |
| S12 | WIKI 写入 | ❌ | 生成 Markdown 文件 |

## 5. WIKI 文件格式

每个生成的 WIKI 文件包含：

1. **YAML frontmatter**（元数据）
2. **12 章节**（对应 12 步处理结果）

示例：
```markdown
---
date: 2026-08-02
title: "到西安与票圈郭小艳..."
type: meeting
file_hash: c1fca66c828c
generator: pj102-llm-meetingkb-v1.0
llm_provider: minimax
---

# 标题

## 📌 基础信息（S1）
## 🎬 场景识别（S2）
## 📋 标准摘要（S3）
## 🔍 FJV 三分法（S4）
## 🧠 隐性知识（S5）
## 🏷️ 5 类实体（S6）
## ✅ 决策和行动项（S7）
## ⚠️ 风险与盲区（S8）
## 📚 知识归类（S9）
## 🧬 认知提炼（S10）
## ⭐ 价值评级（S11）
```

## 7. 常见问题

### Q1: 为什么跑批这么慢？

**A**: 12 步处理，每步 LLM 调用 10-15 秒，总计约 135 秒/文件。**全量 255 个约 9.6 小时**。

### Q2: 能否跳过某一步？

**A**: 当前所有步骤串行执行。如需跳过某步骤，可以修改 `pipeline.py` 注释掉对应行。

### Q3: 能否处理自定义文件？

**A**: 可以。复制文件到 `system/data/raw/`，更新 `system/data/index.json`，跑批即可。

### Q4: 如何切到 DeepSeek？

```bash
export DEEPSEEK_API_KEY="..."
export MINIMAX_API_KEY=""  # 禁用
python3 pipeline.py
```

### Q5: 如何备份？

```bash
tar -czf /tmp/pj102_backup_$(date +%Y%m%d).tar.gz \
  /mnt/d/BaiduSyncdisk/hermes/01-项目/PJ-102-LLM-MeetingKB/
```
