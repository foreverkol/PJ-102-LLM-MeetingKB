#### 容错机制
```
LLM 调用失败 → 检查状态码
├─ 200 → 返回内容
├─ 429 → sleep + 重试（最多 3 次）
├─ 401 → 报错（API key 问题）
├─ 5xx → sleep + 重试
└─ 其他 → 记录日志 + 返回空
```

#### JSON 解析容错
```
原始返回
├─ 移除 ```json 包裹
├─ 提取 { ... } 块
├─ 尝试 json.loads()
│  ├─ 成功 → 返回
│  └─ 失败 → 移除尾随逗号 →重试
│     ├─ 成功 → 返回
│     └─ 失败 → 返回默认值（不阻塞）
```

### 2.4 输出层

#### WIKI 目录结构
```
02-知识库/PJ-102-LLM-MeetingKB/
├── meetings/              （每个源文件 1 个）
│   └── meeting_{date}_{content_hash}.md
├── persons/                （每个说话人 1 个）
│   └── person_{hash6}-{name}.md
├── concepts/               （每个源文件 1 个）
│   └── concept_{date}_{content_hash}.md
├── judgments/              （每个源文件 1 个）
│   └── judgment_{date}_{content_hash}.md
└── comparisons/            （每个源文件 1 个）
    └── comparison_{date}_{content_hash}.md
```

#### 文件命名规范
- `date`：从源文件名提取（YYYY-MM-DD）
- `content_hash`：sha256 前 12 位
- `name`：说话人姓名（URL 编码）

  ↓

  ↓

  ↓

  ↓
