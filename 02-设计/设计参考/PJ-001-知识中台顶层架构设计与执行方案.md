## 第零章：为什么做这件事

### 0.1 这不是文档项目

这不是"把文件存起来"。这是**把王老师20年产业金融认知体系化、系统化、可继承**。

| 短期价值（1-3月） | 中期价值（3-12月） | 长期价值（1-10年） |
|:----------------:|:-----------------:|:-----------------:|
| 见银行前快速复盘上次聊了什么 | 新合伙人能快速"对接"王老师的认知 | 数字人继承思维模式 |
| 创业决策有历史参考 | 竞品情报自动归集+分析 | 知识可传承 |
| 写作/演讲有结构化素材 | 团队认知对齐 | 经验复利增长 |

### 0.2 风险判断

最大风险不是技术，是**半途而废**。所以必须：
- 第一周跑通"输入→编译→输出→使用"的完整闭环
- 让王老师每天都能看到"这个东西有用"
- 不能先建半年的架构再验证

### 1.2 每层与LLM-Wiki的映射

| 数据层 | LLM-Wiki层 | 目录 | 处理方式 |
|:-----:|:----------:|:----:|:--------:|
| 录音类 | L1→RAW/transcripts/ | 转写原文，按年归档 | 流水线自动：转写→分离→确认→摘要 |
| 内部文档 | L1→RAW/documents/ | 按类型分4类 | 手动/批量导入，提取→摘要→入库 |
| 外部知识 | L1→RAW/external/ | 文章/研报/AI笔记 | 剪藏→筛选→摘要→内化 |
| 个人认知 | L1→RAW/personal/ + L3→WIKI/DigitalHuman/ | 原文在RAW，编译在WIKI | 王老师写→结构化→数字人语料 |

### 1.3 关键设计：多设备录音的统一入口

不同来源的录音最终统一进入一个inbox：

```
手机录音 ──→ Syncthing ─┐
其他设备录音 ──→ 手动导入 ─┼──→ ~/wiki/raw/audios/ ──→ Pipeline ──→ RAW/transcripts/YYYY/
他人发来录音 ──→ 微信转发 ─┘
```

**规则**：
- 所有录音文件的原始音频放 `RAW/audios/`（按年份子目录）
- 转写原文放 `RAW/transcripts/YYYY/`
- 音频文件是L1不可变的，不删除，不修改
- 处理完成后从inbox移入archive

## 第三章：人员角色归属体系（完整设计）

### 3.1 三维归属模型

每个人同时从三个维度归属：

```
人（王老师）
  ├─▶ 组织归属（当前在哪个机构、历史在哪些机构、担任什么角色）
  ├─▶ 项目归属（参与了哪些业务项目、在项目中什么角色）
  └─▶ 客户归属（负责对接了哪些客户/渠道/合作方）

人（陈瑛）
  ├─▶ 组织：微众银行（某业务线负责人）
  ├─▶ 项目：贷转票转化率提升项目（外部合作方）
  └─▶ 客户：无（陈瑛是合作方，不是客户）
      └─▶ 关系网络：引荐黄娜 → 对接李洋 → 合作王老师
```

### 3.4 关系网络自动关联

王老师提到了"陈瑛引荐黄娜"，那么在：
- 陈瑛页：关系网络字段记录「→ 黄娜（引荐）」
- 黄娜页：关系网络字段记录「← 陈瑛（被引荐）」
- 系统可以自动检查双向引用是否对称

```yaml
verified_status: disputed

```

## 第四章：全流程机制（七大机制）

### 4.1 摄入机制（Ingest）

**场景**：新录音到达、新文档入库、新文章剪藏

**录音摄入流**（复用已有Pipeline）：
```
手机录音 → inbox/audio/
    ↓
Pipeline自动检测
    ↓
[1] GPU转写（faster-whisper）
[2] 说话人分离（diarize）
[3] 声纹匹配（78维MFCC → SQLite）
[4] 繁简转换（opencc）
[5] 生成标注模板 → 等待确认
[6] 确认后生成最终版
    ↓
自动创建Sources/摘要页
    ↓
触发WIKI编译（检查Entities/Concepts/Knowledge是否需要更新）
```

**文档摄入流**：
```
内部文档 → 手动放入 RAW/documents/分类/
    ↓
AI读取，提取关键信息
    ↓
创建Sources/documents/摘要
    ↓
更新对应的Entities、Concepts
    ↓
标记为archive
```

### 4.2 编译机制（Compile — 对应LLM-Wiki核心）

**触发条件**：
- 每次有新的Sources页面创建后
- 每次有新的Judgment加入后
- 定时编译（每日/每周）

**编译内容**：
- 检查新信息是否涉及已知实体 → 更新或创建
- 检查新信息是否涉及已知概念 → 更新或创建
- 提取判断 → 更新Knowledge/Judgments/或创建新判断
- 提取决策线索 → 更新Knowledge/Decisions/
- 补充wikilink（两遍链接算法）
- 更新index.md和log.md

### 4.3 查询机制（Query）

**王老师问问题 → AI从WIKI回答**（不是从原始录音检索）：

```
"上次跟微众银行聊了什么？"
    ↓
→ 读取Entities/Organizations/微众银行.md
→ 读取Sources/transcripts/中相关摘要
→ 读取Knowledge/Judgments/中的相关判断
→ 综合回答：合作历史 + 关键判断 + 待跟进事项
```

### 4.4 异议/矛盾机制（Objection — ★ 新增）

**当新知识与旧知识冲突时**：

```
新录音说 "贷转票模式不行了"
旧Judgment说 "贷转票是核心方向"
```

**处理流程**：
1. AI检测到矛盾
2. 不删除旧判断，不覆盖
3. 创建新判断，frontmatter中标注：
   ```yaml
   evolved_from: "关于_贷转票_判断_2024.md"
   contradicts: true
   ```
4. 在旧判断页加反向引用
5. 在log.md中记录矛盾事件
6. 在下次Lint报告中标出待处理矛盾

**判断演变追踪**：
```
2024-06: "贷转票是核心方向"（strong）
    ↓
2025-03: "纯贷转票利润太薄"（moderate）【evolved_from 上一个】
    ↓
2025-09: "贷转票只能作为入口产品"（speculative）【evolved_from 上一个】
    ↓
当前：待确认最准确的版本
```

### 4.5 校验机制（Lint — 定期健康检查）

**检查频率**：每处理10个录音后，或每周自动

**检查项**（引用claude-memory-compiler的Lint 7检查）：

| 检查项 | 描述 | 严重程度 |
|:------:|:----|:--------:|
| 孤儿页 | 没有被任何其他页面链接 | 中 |
| 断链 | [[wikilink]]指向不存在的页面 | 高 |
| 矛盾 | 同一主题存在冲突信息 | 高 |
| 过期 | 超过90天未更新的活跃实体 | 低 |
| 无来源 | 页面没有source_ref字段 | 高 |
| 无标签 | 页面缺少tags | 低 |
| 过长 | 超过200行的页面 | 中 |

**处理**：
- 孤儿页 → 补链或归档
- 断链 → 创建页面或修正链接
- 矛盾 → 发起矛盾处理流程
- 报告 → 追加到log.md，通知王老师

### 4.6 定时机制（Timing — ★ 新增）

| Cron任务 | 频率 | 动作 |
|:--------:|:----:|:----:|
| 录音检测 | 每1小时 | 检查inbox/audio/有无新文件，触发Pipeline |
| 编译 | 每24小时 | 检查新Sources，触发编译 |
| Lint | 每7天 | 执行全库健康检查 |
| 矛盾提醒 | 每1天 | 检查是否有新矛盾待确认 |
| 数字人语料推送 | 每30天 | 检查DigitalHuman/是否有未确认内容 |
| 文件清理 | 每30天 | 检查archive是否需要压缩 |
| 磁盘检查 | 每7天 | 检查WSL磁盘空间 |

### 4.7 同步机制（Sync — ★ 王老师特别强调）

**架构图**：
```
手机（华为备忘录）
    ↓ Syncthing（手机端）
Windows百度网盘同步盘
  D:\BaiduSyncdisk\
    ↓ WSL挂载 /mnt/d/
WSL（所有后台处理都在这里）
    ↓ 处理后写回
WIKI文件（在/mnt/d/下）
    ↓
Obsidian（Windows端）自动读取
```

**为什么全在WSL**：
- Windows不能长期运行常驻服务
- WSL可以：Cron + Pipeline + 定时任务
- Obsidian在Windows端作为展示层只读

**同步规则**：
```
录音同步：手机 → Syncthing → Windows → WSL挂载 → WSL Pipeline
知识库同步：WSL编译 → 写入WIKI文件（/mnt/d/） → Obsidian自动读取
配置同步：WSL ↔ 百度网盘（备份）
```
