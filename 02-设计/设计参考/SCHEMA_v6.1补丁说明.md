## v6.1 补丁内容

### 补丁1：五要素摘要增加「判断标注」字段（⭐⭐⭐⭐⭐）

**现状**：五要素摘要中，判断句和事实句混在一起，无法区分发言人的主观判断和客观事实。

**v6.1补丁**：在五要素摘要的每条内容后面，增加 `[判断:发言人]` 标注：

```markdown
## 五要素摘要
- **背景**：[事实陈述] [判断:郭葉教授]
- **问题**：[客观描述的问题] [判断:陈中平洋教授]
- **方法**：[方案描述]（方法一般属于事实，较少判断）
- **结果**：[达成的共识/成果] [判断:李市长]
- **启示**：[对未来指导意义]（此处通常是发言人的推断，属于判断）
```

**判断句判断标准**：
- 含「觉得/认为/相信/判断/估计/可能/应该/看来/估计是」→ 判断
- 含具体数字/日期/名称 → 事实
- 行动计划（「要/将/会/计划」）→ 事实/愿景，不标判断
- 「国内低风险」→ 判断（主观评估）
- 「已签约」→ 事实（有具体行为）

**示例**（基于梁超杰20260529录音）：
```
- **方法**：采用"三线并行"策略：
  1. 国内线：与海塑教、正宿交易中心、新国链网签约，建立可信数据共享平台
     ✅ 事实（具体行为）
  2. 境外线：利用香港数字资产平台，推荐合规资产
     ✅ 事实（具体描述）
  3. 学术线：与下关大学合作成立研究中心
     ✅ 事实（具体行为）
- **启示**：「资源整合是关键」——[判断:发言人]
  「利用学术机构的品牌和背书可以快速建立信任」——[判断:发言人]
```

### 补丁2：增加「定量金融参数」字段（⭐⭐⭐⭐）

**现状**：五要素摘要中有金额/利率信息，但散落在正文里，无法快速检索。

**v6.1补丁**：在 Meeting 页增加独立字段：

```markdown
## 定量金融参数
| 参数类型 | 数值 | 来源句 | 发言人 |
|---------|------|--------|--------|
| 额度 | 3000万元 | 「额度可以给到3000万」 | 刘总 |
| 利率 | 4.35% | 「利率大概在4.35%左右」 | 王老师 |
| 期限 | 6个月 | 「周期的话6个月以内」 | 刘总 |
| 保证金 | 10% | 「保证金需要10个点」 | 刘总 |
| 营业收入 | 2亿元 | 「去年营收2个亿」 | 俞东祥 |
```

**参数类型枚举**：
- 额度 / 授信金额
- 利率 / 费率
- 期限 / 账期
- 保证金比例
- 营业收入
- 净利润
- 目标市场规模
- 客单价
- 其他关键数字

**抓取规则**：
- 必须有具体数字（万/亿/千/%)
- 必须标注来源句（原文引用）
- 必须标注发言人（用于追溯）

### 补丁3：Tags增加「可转化资产」标记（⭐⭐⭐⭐）

**现状**：Tags只用于分类，无法区分哪些内容可转化为对外素材。

**v6.1补丁**：在Tags中增加以下标记：

```markdown
tags: [
  # 分类
  #meeting #供应链金融 #金融科技 #产业互联网 #创业 #融资

  # 可转化资产（新增）
  #BP素材     # 可用于商业计划书的背景描述/市场分析
  #官网文案   # 可用于官网公司介绍/产品介绍
  #销售话术   # 可用于销售团队培训/话术整理
  #演讲素材   # 可用于公开演讲/论坛分享
  #客户案例   # 可作为客户案例对外展示
]
```

**标记使用规则**：
- `#BP素材` — 背景描述、市场痛点、商业模式、市场规模数据
- `#官网文案` — 公司介绍、产品说明、核心优势、服务案例
- `#销售话术` — 客户常见问题解答、产品卖点话术、竞品对比话术
- `#演讲素材` — 行业趋势判断、方法论、案例故事
- `#客户案例` — 成功合作经历、客户背景、解决方案、成果数据

### 补丁4：meeting_type 扩展为6类（⭐⭐⭐）

**现状**：`meeting_type: business_discussion` 分类过于粗略，无法区分场景。

**v6.1补丁**：meeting_type 扩展为6类，frontmatter 精细化：

```yaml
---
type: meeting
meeting_type: client_visit    # 扩展为6类（见下）
meeting_subtype: first_meet | follow_up | negotiation | contract_sign | project_kickoff | regular_review
---
```

**meeting_type 6类分类**：

| 类型值 | 含义 | 典型场景 |
|--------|------|---------|
| `client_visit` | 客户拜访/需求交流 | 首次拜访、需求挖掘、方案讨论 |
| `bank_communication` | 银行交流 | 银行拜访、授信谈判、风控沟通 |
| `investor沟通` | 投资沟通 | VC/PE路演、投资人尽调、条款谈判 |
| `partner_coordination` | 合作方协调 | 渠道方对接、资源方洽谈、合作方案 |
| `internal_review` | 内部复盘 | 团队会议、项目复盘、战略讨论 |
| `industry_exchange` | 行业交流 | 论坛参会、行业协会、同业交流 |
| `personal_thinking` | 个人思考 | 录音自言自语、分析判断、无外部参与 |

**meeting_subtype 补充**（可选）：

| 子类型 | 适用场景 |
|--------|---------|
| `first_meet` | 首次接触 |
| `follow_up` | 后续跟进 |
| `negotiation` | 商务谈判 |
| `contract_sign` | 签约 |
| `project_kickoff` | 项目启动 |
| `regular_review` | 定期回顾 |

## 补丁实施优先级

| 补丁 | 优先级 | 理由 |
|------|--------|------|
| 补丁1（判断标注） | ⭐⭐⭐⭐⭐ 立即执行 | 核心认知价值，直接影响判断质量 |
| 补丁2（金融参数） | ⭐⭐⭐⭐ 立即执行 | 金融场景核心数据，当前完全缺失 |
| 补丁3（可转化资产） | ⭐⭐⭐ 批量时执行 | 批量处理时顺手标注，不额外增加工时 |
| 补丁4（meeting_type扩展） | ⭐⭐⭐ 批量时执行 | 批量处理时根据内容判断，工时增加少 |

## 补丁对现有产出的影响

| 影响项 | 说明 |
|--------|------|
| 已有 Meeting 页 | **不重跑**，新补丁仅适用于新增/更新的页面 |
| P2 提取 Prompt | 需要更新 MiniMax 调用 Prompt，告知新增字段 |
| 批量处理 | 新字段在批量处理时自动带上，工时增加约5% |
| 实体页（Person/Org） | 不受影响，仅 Meeting 页有变化 |
