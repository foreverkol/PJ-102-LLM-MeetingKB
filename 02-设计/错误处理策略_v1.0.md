# PJ-102-LLM-MeetingKB · 错误处理策略 v1.0

## 1. 错误分类

### 1.1 网络错误

| 错误 | 触发 | 处理 |
|---|---|---|
| 连接超时 | 网络不稳定 | 重试 3 次，exponential backoff |
| 429 限流 | 调用过快 | sleep + 重试 |
| 401 鉴权失败 | API key 错误 | 报错并退出 |
| 5xx 服务异常 | LLM 服务端问题 | 重试 3 次 |

### 1.2 解析错误

| 错误 | 触发 | 处理 |
|---|---|---|
| JSON 解析失败 | LLM 返回非标准 JSON | safe_json_parse 容错 |
| Markdown 包裹 | LLM 返回 ```json 包裹 | 移除包裹 |
| 字段缺失 | LLM 漏字段 | 使用默认值 |
| 类型错误 | LLM 返回非预期类型 | 类型转换或默认值 |

### 1.3 业务错误

| 错误 | 触发 | 处理 |
|---|---|---|
| 源文件缺失 | path 不存在 | FileNotFoundError |
| 编码错误 | 文件非 UTF-8 | 尝试 GBK 兜底 |
| 内容为空 | 0 字节 | 跳过 + 日志 |
| LLM 返回空 | 调用成功但内容为空 | 使用默认值 |

## 2. 重试策略

### 2.1 LLM 调用重试

```python
def call_with_retry(self, prompt, max_retries=3):
    for attempt in range(max_retries):
        try:
            return self._call_llm(prompt)
        except HTTPError as e:
            if e.code == 429:
                wait = 2 ** attempt  # 1s, 2s, 4s
                logger.warning(f"限流，等待 {wait}s")
                time.sleep(wait)
            elif e.code == 401:
                logger.error("API key 无效")
                raise  # 不重试
            else:
                logger.warning(f"HTTP {e.code}")
                time.sleep(2 ** attempt)
        except TimeoutError:
            logger.warning("调用超时")
            time.sleep(2 ** attempt)
        except Exception as e:
            logger.exception(e)
            return ""  # 重试用尽
    return ""
```

### 2.2 单文件处理策略

- 单文件失败不影响其他文件
- 失败信息记录到 system/logs/error.log
- 继续处理下一个文件
- 失败的可以后续单独重跑

### 2.3 整体中断策略

```bash
# Ctrl+C 优雅退出
SIGINT handler:
    1. 完成当前文件
    2. 保存状态到 state.json
    3. 打印进度报告
    4. 退出

# 重新运行（自动跳过已完成的）
python3 pipeline.py  # 增量运行
```

## 3. 容错机制

### 3.1 JSON 解析容错

```python
def safe_json_parse(content, default):
    if not content:
        return default
    
    # 1. 清理 markdown 包裹
    content = re.sub(r"^```(?:json)?\s?", "", content)
    content = re.sub(r"\s?```$", "", content)
    
    # 2. 提取 JSON 块
    m = re.search(r"\{[\s\S]*\}", content)
    if m:
        content = m.group(0)
    
    # 3. 尝试解析
    try:
        return json.loads(content)
    except json.JSONDecodeError:
        pass
    
    # 4. 修复常见错误
    content = re.sub(r",\s*}", "}", content)
    content = re.sub(r",\s*]", "]", content)
    
    try:
        return json.loads(content)
    except:
        return default
```

## 4. 日志策略

### 4.1 日志级别

| 级别 | 用途 |
|---|---|
| DEBUG | 详细调试信息（默认关闭）|
| INFO | 关键节点（开始/完成）|
| WARNING | 非致命问题（限流/超时）|
| ERROR | 致命错误（API key 失败）|

### 4.2 日志格式

```
2026-09-03 19:58:30 INFO [pipeline] 开始处理 sample_001
2026-09-03 19:58:35 INFO [s1] 完成: 2026-08-02
2026-09-03 19:58:50 INFO [s2] 调用 LLM (prompt=2049 chars)
2026-09-03 19:59:05 WARNING [s3] LLM 429, 重试 1/3
2026-09-03 19:59:10 INFO [s3] 完成
...
2026-09-03 20:01:30 INFO [pipeline] 完成: 13.5s
```

### 4.3 日志文件

```
system/logs/
├── pipeline.log       (主日志)
├── error.log          (错误日志)
├── llm_call.log       (LLM 调用详情)
└── progress.json      (实时进度)
```
